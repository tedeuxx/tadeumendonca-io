# Product ADRs — tadeumendonca.io

Architecture Decision Records for the **product** — the current stack and architectural vision of the
site. Taken together, these ADRs *are* the architecture documentation: every load-bearing decision, and
the reversed ones recorded under **History**.

**What belongs here, and the rule a new decision passes to get in:**
[0053](./0053-this-library-records-presence-and-site-architecture-one-document-per-capability.md) — the
library records decisions about the owner's online presence and the site's technical architecture, one
document per capability, and a new decision passes a two-limb entry rule (*does a capability document
already hold it?* and *does a mechanism already refuse the alternative?*) before it becomes a file.

Practice, format and lifecycle: the method's `documentation-standard` skill, Part II (MADR, the
significance test, and the four dispositions of a record that leaves the library). ~~supersede-never-delete~~
— **struck 2026-11-01 (#456):** the practice replaced it, and so does this library; see *History* below.
Methodology decisions (the dev-loop machine) live in the method's own library.

**Numbering:** append-only in authoring order. The reading groups below are presentation; a decision's
number is fixed once its file exists. A superseded ADR carries the forward link to the ADR that replaced
it (the replacement does not depend on the superseded one's number).

**Reading order:** the keystone is *lean by design, calibrated to strategy*, and every other ADR is read
through it. It was record 0001 until #456 absorbed it into [ADR-0053](./0053-this-library-records-presence-and-site-architecture-one-document-per-capability.md#lean-by-design--the-keystone-every-record-is-read-through), whose section *Lean by design
— the keystone every record is read through* now holds it.

**How a statement that stopped being true is marked** (settled by the #234 sweep, 2026-07-29). *Supersede,
never rewrite* is the rule; it has **three** shapes, and which one applies depends on whether the original
was a decision, a premise, or a passing reference:
- **Strike + discharge** — for a **decision or accepted cost** that was reversed. The reader must still see
  what was decided. `~~old text~~ **→ discharged <date> by ADR-00NN**`.
- **Rewrite + parenthetical** — for an **incidental reference** (a route name, a file, a cross-ADR
  citation) whose only job is to point somewhere. Striking these buries the working pointer under a dead
  one, so the text is corrected and the original noted in a parenthetical.
- **Leave + flag** — where another ADR has already claimed the reference as deliberate history (e.g.
  ADR-0010's carve-out for `/cv`). The text stays; a note says so, because that carve-out is invisible
  from the file that carries the reference.

**Enforcement: none, and deliberately** (#234's open question). A check can assert that a *listed* path
resolves; it cannot know a claim quietly stopped being true — which is every finding in the #234 sweep.
So the library is **audited by reading**, and the moment is **when an ADR is amended**: an amendment is
where one record changes what another asserts, and every one of the thirteen findings originated exactly
there. Same answer, and the same reason, as the root `CLAUDE.md` records for itself (#233).

**Checked, not trusted.** `apps/fed/scripts/adr-capabilities.test.mjs` fails in each of these cases:

- a record has no `Capability:` line, or more than one;
- a record's line and its row here disagree;
- a record sits in no cell, or in two;
- a cell names a number that has no file;
- a capability row has no single anchor;
- a record in the deactivation column is not `superseded`, or a `superseded` record sits in any other column.

It does not judge whether a record is in the *right* capability. That is a reading, and the fold slice
that moves the record is where it happens.
